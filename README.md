# نظام تصنيف الصور مع تحسين ذاتي مُراقَب

مشروع تدريب وتقييم وتحسين لنموذج تصنيف صور إلى ثلاث فئات (مجلدات الأرشيف):

| الفئة | المعنى |
|---|---|
| `مشوش` | صور مشوشة/غير واضحة |
| `من هاتف` | صور بطاقة مصوّرة من هاتف |
| `ممسك للهوية من هاتف` | شخص ممسك للهوية، مصوّر من هاتف |

> ملاحظة: أسماء الفئات مأخوذة من أسماء المجلدات. إذا كان المعنى مختلفًا، عدّل الأسماء في المجلدات فقط وأعد تشغيل `prepare_data`.

## ما الذي يعنيه "دقة 100%"؟

لا يوجد نموذج يعطي **صفر خطأ** على كل صورة مستقبلية، وأي وعد بذلك غير صادق. ما يقدمه هذا المشروع:

1. **تدريب احترافي** بنقل التعلم (transfer learning)، وتوازن الفئات، وتعزيز بيانات مناسب للهويات (بدون قلب أفقي)، وearly stopping.
2. **تقييم صارم** على تقسيم اختبار ثابت لا يُلمس، مع macro-F1 ومصفوفة الارتباك ومعايرة الثقة.
3. **قبول تلقائي بعتبة ثقة**: الصورة تُقبل تلقائيًا فقط إذا كانت الثقة عالية بما يكفي لتحقيق دقة الهدف (افتراضيًا 98%) على تقسيم التحقق. الباقي يذهب **للمراجعة البشرية** بدل التخمين.
4. **حلقة تحسين ذاتي**: الصور المراجعة بشريًا تُضاف للتدريب، ويُرقّى النموذج الجديد **فقط** إذا تفوق على الحالي على الاختبار الثابت دون تراجع في أي فئة.

## الهيكل

```
src/prepare_data.py   استخراج الأرشيف، التحقق من الصور، إزالة التكرار، التقسيم الطبقي، ضبط المسارات
src/dataset.py        تحميل الصور والتحويلات
src/model.py          بناء النموذج (EfficientNet-B0 / ResNet50 / MobileNetV3)
src/metrics.py        المقاييس، ECE، اختيار عتبة القبول
src/evaluate.py       تحميل نقاط الحفظ وتقييمها + مسح العتبات (--sweep)
src/train.py          التدريب
src/predict.py        التنبؤ بصور جديدة + تسجيلها للمراجعة
src/feedback.py       قاعدة المراجعة، الإحصاءات، سجل الإصدارات، إعادة التدريب والترقية
src/paths.py          حلّ المسارات ليعمل المشروع على أي جهاز
src/app.py            واجهة ويب للتنبؤ والمراجعة البشرية
templates/            صفحات الواجهة
tests/                اختبارات الوحدات
```

## التثبيت

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## الخطوة 1: تجهيز البيانات

الأرشيف `من 100 الى 300.rar` موجود في المستودع. فك ضغطه يحتاج أداة `unrar` أو `7z` على النظام:

```bash
python -m src.prepare_data --archive "من 100 الى 300.rar" --raw-dir data/raw
```

أو فكّه يدويًا داخل `data/raw/` ثم شغّل الأمر بدون `--archive`. تُنتج الأداة `data/processed/splits.csv` و`classes.json` وتقرير المكررات.

**نقل المشروع إلى جهاز آخر:** المسارات تُكتب نسبية عن جذر المشروع، وإن كان ملف `splits.csv` قديمًا فيه مسارات مطلقة
من جهاز آخر (مثل `D:\...`) فلا تُغيّر التقسيم، بل أعد ضبط المسارات فقط:

```bash
python -m src.prepare_data --rebase     # يطابق الصور بالبصمة sha256 ويحافظ على train/val/test كما هو
```

## الخطوة 2: التدريب

```bash
python -m src.train --arch efficientnet_b0 --img-size 224 --epochs 30 --out-dir runs/baseline
```

يحتاج الأمر أولًا إلى تحميل الأوزان المدربة مسبقًا من ImageNet (تحدث تلقائيًا عند أول تشغيل مع إنترنت). التدريب من الصفر (`--no-pretrained`) لا يتعلم شيئًا تقريبًا على 200 صورة، لذا لا تستخدمه إلا للاختبار.

النتائج في `runs/baseline/metrics.json`، والنموذج في `runs/baseline/model.pt`.

## الخطوة 2-ب: تقييم أي نقطة حفظ

```bash
python -m src.evaluate --checkpoint runs/baseline/model.pt --info      # بيانات النموذج فقط
python -m src.evaluate --checkpoint runs/baseline/model.pt --split test
python -m src.evaluate --checkpoint runs/baseline/model.pt --split all --out runs/baseline/eval_report.json
python -m src.evaluate --checkpoint runs/baseline/model.pt --split val --sweep   # دقة المقبولات عند كل عتبة
```

`--sweep` يعرض جدولًا لكل عتبة من 0.50 إلى 0.99: كم نسبة ما يُقبل تلقائيًا، وما دقة المقبولات فعلًا.
هذا هو الأساس لاختيار **نقطة تشغيل** صريحة بدل الاعتماد على عتبة اختيرت مرة واحدة.

## الخطوة 3: تسجيل النموذج كإصدار إنتاجي

```bash
python -m src.feedback register --checkpoint runs/baseline/model.pt --version v1
```

## الخطوة 4: التنبؤ بصور جديدة

```bash
python -m src.predict --checkpoint models/production/model.pt new_images/ \
    --out predictions.csv --feedback-db feedback/feedback.db
```

لكل صورة: `accept` (قبول تلقائي) أو `review` (تحتاج مراجعة)، مع الثقة والاحتمالات.

## الخطوة 5: المراجعة وتحسين النموذج

```bash
python -m src.feedback pending --limit 20            # الصور التي تحتاج مراجعة (الأقل ثقة أولًا)
python -m src.feedback label --id 12 --label "من هاتف" --reviewer name
python -m src.feedback status                         # دقة كل إصدار على الصور المراجعة
python -m src.feedback retrain --min-new 20           # إعادة تدريب وترقية إن تحسن
```

قواعد الأمان في `retrain`:
- صور **val/test** لا تدخل التدريب أبدًا، حتى لو صُنّفت بشريًا، لأن ذلك يُفسد التقييم.
- الترقية تتطلب تحسن macro-F1 على الاختبار الثابت، ولا تنخفض recall لأي فئة بأكثر من 5%.
- كل قرار مسجل في `models/registry.json` مع أسبابه.
- مع عدد صور اختبار صغير (حوالي 30) يكون التباين كبيرًا، لذا يُنصح بزيادة البيانات المصنفة وإعادة تقييم القرار.

## الخطوة 6: واجهة ويب للتنبؤ والمراجعة

```bash
python -m src.app --port 7860        # ثم افتح http://localhost:7860
```

- **التنبؤ**: رفع صورة أو أكثر، عرض الفئة والثقة وقرار `accept/review`، مع إمكانية تصحيح النتيجة بضغطة زر.
- **المراجعة**: طابور الصور غير المصنّفة (الأقل ثقة أولًا) مع أزرار التصنيف — وهو أسرع بكثير من سطر الأوامر.
- **واجهة برمجية**: `POST /api/predict` يرفع صورًا ويُعيد JSON، و`GET /api/status` يعرض حالة النموذج والإحصاءات.

كل تنبؤ يُسجَّل في `feedback/feedback.db`، أي أن الواجهة نفسها تغذي حلقة التحسين الذاتي.

## نتائج الإصدار الحالي (v1)

نقطة الحفظ `runs/baseline/model.pt` (EfficientNet-B0، 224px، عتبة 0.75، T=0.48) قُيّمت على التقسيم الثابت:

| التقسيم | عدد الصور | الدقة | macro-F1 | ECE |
|---|---|---|---|---|
| train | 149 | 100% | 1.000 | 0.017 |
| val | 31 | 87.1% | 0.875 | 0.093 |
| **test** | **31** | **77.4%** | **0.792** | **0.186** |

لكل فئة على الاختبار: `مشوش` F1=0.79 (recall 0.93)، `ممسك للهوية من هاتف` F1=0.89، `من هاتف` F1=0.70 (recall 0.58).

**قراءة صادقة للنتيجة:**
1. الفرق بين التدريب (100%) والاختبار (77%) يعني **تخصيصًا زائدًا (overfitting)** واضحًا: 149 صورة تدريب قليلة على شبكة بكفاءة ImageNet. هذا هو سبب الدقة المحدودة، لا عيب في خطوة التقييم.
2. تقسيم الاختبار 31 صورة فقط، أي أن ±6 صور تغيّر الدقة بمقدار ~20 نقطة مئوية. الأرقام أعلاه **مؤشر** لا قياس نهائي.
3. العتبة 0.75 اختيرت على 31 صورة تحقق فقط، فجاءت دقة المقبولات 100% على التحقق لكن **76.7%** على الاختبار — دليل على أن ضبط العتبة يحتاج تقسيم تحقق أكبر. نقطة تشغيل أكثر أمانًا حتى يتوفر ذلك: **0.90–0.95** (تُقبل 77–87% من الصور بدقة 82–92% على الاختبار)، أو 0.99 إن كان الخطأ مكلفًا جدًا (45% فقط تُقبل، بدقة 100%).

**كيف نرفع الدقة فعلًا** (بالترتيب حسب الأثر المتوقع):
1. **جمع بيانات أكثر** — الهدف مئات الصور لكل فئة لا عشراتها؛ هذا وحده يحل معظم التخصيص الزائد.
2. **توسيع تقسيم التحقق** (مثل 20% بدل 15%) أو تقييم متعدد البذور (cross-validation) قبل اعتماد أي عتبة.
3. **تدريب أقصر وأكثر تنظيمًا**: تجميد العمود الفقري لل epochs الأولى، `weight_decay` أعلى، `lr` أصغر (1e-4)، وإيقاف أبكر.
4. **مراجعة التسميات**: صور `من هاتف` و`مشوش` المتشابهة هي مصدر الخلط الأكبر (5 من 12 صورة `من هاتف` صُنّفت `مشوش`).
5. تشغيل `python -m src.feedback retrain --min-new 20` بعد كل دفعة مراجعة بشرية — الترقية تلقائية ومشروطة بعدم التراجع.
