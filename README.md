# نظام تصنيف الصور مع تحسين ذاتي مُراقَب

مشروع تدريب وتقييم وتحسين لنموذج تصنيف صور إلى ثلاث فئات (مجلدات الأرشيف):

| الفئة | المعنى |
|---|---|
| `مشوش` | صور مشوشة/غير واضحة |
| `من هاتف` | صور بطاقة مصوّرة من هاتف |
| `ممسك للهوية من هاتف` | شخص ممسك للهوية، مصوّر من هاتف |

> ملاحظة: أسماء الفئات مأخوذة من أسماء المجلدات. إذا كان المعنى مختلفًا، عدّل الأسماء في المجلدات فقط وأعد تشغيل `prepare_data`.

## ما الذي يعنيه "دقة 100%"؟

لا يوجد نموذج يعطي **صفر خطأ** على كل صورة مستقبلية، وأي وعد بذلك غير صادق. ما يقدمه هذا المشروع:

1. **تدريب احترافي** بنقل التعلم (transfer learning)، وتوازن الفئات، وتعزيز بيانات مناسب للهويات (بدون قلب أفقي)، وearly stopping.
2. **تقييم صارم** على تقسيم اختبار ثابت لا يُلمس، مع macro-F1 ومصفوفة الارتباك ومعايرة الثقة.
3. **قبول تلقائي بعتبة ثقة**: الصورة تُقبل تلقائيًا فقط إذا كانت الثقة عالية بما يكفي لتحقيق دقة الهدف (افتراضيًا 98%) على تقسيم التحقق. الباقي يذهب **للمراجعة البشرية** بدل التخمين.
4. **حلقة تحسين ذاتي**: الصور المراجعة بشريًا تُضاف للتدريب، ويُرقّى النموذج الجديد **فقط** إذا تفوق على الحالي على الاختبار الثابت دون تراجع في أي فئة.

## الهيكل

```
src/prepare_data.py   استخراج الأرشيف، التحقق من الصور، إزالة التكرار، التقسيم الطبقي
src/dataset.py        تحميل الصور والتحويلات
src/model.py          بناء النموذج (EfficientNet-B0 / ResNet50 / MobileNetV3)
src/metrics.py        المقاييس، ECE، اختيار عتبة القبول
src/evaluate.py       تحميل نقاط الحفظ وتقييمها
src/train.py          التدريب
src/predict.py        التنبؤ بصور جديدة + تسجيلها للمراجعة
src/feedback.py       قاعدة المراجعة، الإحصاءات، سجل الإصدارات، إعادة التدريب والترقية
tests/                اختبارات الوحدات
```

## التثبيت

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## الخطوة 1: تجهيز البيانات

الأرشيف `من 100 الى 300.rar` موجود في المستودع. فك ضغطه يحتاج أداة `unrar` أو `7z` على النظام:

```bash
python -m src.prepare_data --archive "من 100 الى 300.rar" --raw-dir data/raw
```

أو فكّه يدويًا داخل `data/raw/` ثم شغّل الأمر بدون `--archive`. تُنتج الأداة `data/processed/splits.csv` و`classes.json` وتقرير المكررات.

## الخطوة 2: التدريب

```bash
python -m src.train --arch efficientnet_b0 --img-size 224 --epochs 30 --out-dir runs/baseline
```

يحتاج الأمر أولًا إلى تحميل الأوزان المدربة مسبقًا من ImageNet (تحدث تلقائيًا عند أول تشغيل مع إنترنت). التدريب من الصفر (`--no-pretrained`) لا يتعلم شيئًا تقريبًا على 200 صورة، لذا لا تستخدمه إلا للاختبار.

النتائج في `runs/baseline/metrics.json`، والنموذج في `runs/baseline/model.pt`.

## الخطوة 3: تسجيل النموذج كإصدار إنتاجي

```bash
python -m src.feedback register --checkpoint runs/baseline/model.pt --version v1
```

## الخطوة 4: التنبؤ بصور جديدة

```bash
python -m src.predict --checkpoint models/production/model.pt new_images/ \
    --out predictions.csv --feedback-db feedback/feedback.db
```

لكل صورة: `accept` (قبول تلقائي) أو `review` (تحتاج مراجعة)، مع الثقة والاحتمالات.

## الخطوة 5: المراجعة وتحسين النموذج

```bash
python -m src.feedback pending --limit 20            # الصور التي تحتاج مراجعة (الأقل ثقة أولًا)
python -m src.feedback label --id 12 --label "من هاتف" --reviewer name
python -m src.feedback status                         # دقة كل إصدار على الصور المراجعة
python -m src.feedback retrain --min-new 20           # إعادة تدريب وترقية إن تحسن
```

قواعد الأمان في `retrain`:
- صور **val/test** لا تدخل التدريب أبدًا، حتى لو صُنّفت بشريًا، لأن ذلك يُفسد التقييم.
- الترقية تتطلب تحسن macro-F1 على الاختبار الثابت، ولا تنخفض recall لأي فئة بأكثر من 5%.
- كل قرار مسجل في `models/registry.json` مع أسبابه.
- مع عدد صور اختبار صغير (حوالي 30) يكون التباين كبيرًا، لذا يُنصح بزيادة البيانات المصنفة وإعادة تقييم القرار.
